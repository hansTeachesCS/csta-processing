Robot Drawing

Mild

Turn a robot drawing into Processing shapes.

1. Find it

  • Run it. The head is already drawn.
  • Hover over the canvas to see the mouse position. Which way does y go?

2. Draw it

  • Add the eyes, mouth, body, arms and legs, using the example robot in the instructions.
  • It doesn't have to be an exact match.
  • What should be drawn first so the body overlaps the arms?

3. Make it yours

  • Change colors and add details.
  • Or design your own robot from scratch.

Reference

  • rect() · ellipse()
  • line() · arc()
  • fill() · noFill()
  • stroke() · strokeWeight()

Functions Library: Fall Stamps

Medium

Use (and maybe write) drawing methods to compose a picture.

1. Explore

  • Run it, then press a key to stamp at your mouse.
  • P pumpkin, H haystack, T bare tree, L leaf.
  • Stamp a few leaves. Why does each one land at a different angle?

2. Compose

  • Build a scene by calling stamps in setup().
  • Uncomment the examples to start: pumpkin(500, 320, 0.8);
  • Change the third number to resize: 1.0 is normal, 0.5 is half.

3. Create

  • Copy a stamp method and draw something new: an apple, a scarecrow, a fence.
  • Draw around (0, 0). translate() moves it into place.
  • Call it in setup(), or give it a key in keyPressed().

Reference

  • translate()
  • scale()
  • rotate()
  • pushMatrix() and popMatrix()
  • keyPressed()

Confetti

Challenging

Build objects in an array to animate a confetti burst.

1. Read

  • Run it. One piece of confetti falls over Times Square.
  • Open Confetti.java. What does each piece keep track of?
  • What happens when a piece falls off the bottom?

2. Make it rain

  • Replace piece with 150 pieces, using an array or an ArrayList.
  • Give each one a random size from 3 to 15, the same way piece gets its size.

3. Draw them all

  • In draw(), loop through your pieces.
  • For each one, call drawConfetti() and fall().
  • Bonus: add a burst of new confetti on click with mousePressed().

Tips

  • Array or ArrayList? An array has a fixed size. An ArrayList can grow, which you'll want for the click burst.
  • Create the pieces in setup(), not draw(), or you'll make 150 new ones every frame.
  • ArrayList reference

PRIMM: Traffic Light

Technique

A traffic light that almost works. Read it, run it, figure it out, then make the car obey it.

P

Predict

Read the code without running it. What will you see? What happens when you click each light?

R

Run

Run it and click all three lights. Which predictions were right? What surprised you?

I

Investigate

Which method decides if a click hits the red light? What do 510, 55 and 25 mean? Why can't you get back to green?

M

Modify

Make the yellow and green lights clickable too. Hint: what changes between the three lights?

M

Make

Make the car drive on green, slow down on yellow and stop on red. Bonus: wrap it around the screen.

How this works in the classroom

Keep Predict low-stakesDon't grade predictions. A wrong guess is useful, so everyone feels free to commit to one.
Start from working codeStudents run code you provide instead of a blank editor, which lowers anxiety and avoids confusing errors.
Talk in pairsPredict and Investigate work best in pairs or small groups, away from the keyboard, so students build shared vocabulary.
Vary the InvestigateTrace, annotate, explain and debug. Ask questions pitched just beyond what students can do alone.
Modify in small stepsIncrease difficulty gradually, so the code shifts from someone else's to partly theirs.
Make something newUse the same structures to solve a different problem. Not every lesson needs all five stages.

Parsons Problem

Technique

Put 14 scrambled lines in order to draw the pumpkin.

How to solve it

  • Background first. background() paints over everything drawn before it.
  • Back to front. Shapes drawn later land on top, so draw what's behind first.
  • Colors carry forward. fill(), stroke() and noStroke() apply to every shape after them, until changed.
  • Read the numbers. Match each shape's x and y to where it sits in the target picture.
  • Run often. Move one line, run, compare.

Editor shortcuts

  • Comment a line out or back in: Ctrl + / (Windows) or Cmd + / (Mac). If that doesn't work, type // at the start of the line.
  • Move a line up or down: click the line, then Option + ↑/↓ (Mac) or Alt + ↑/↓ (Windows). No copy and paste needed.
  • Build it up: comment out every line, then bring them back one at a time.
  • Experiment: change a number to see what it controls.
  • Undo: Ctrl/Cmd + Z. Redo: Ctrl/Cmd + Shift + Z.

Reference

  • ellipse()
  • rect()
  • fill()
  • stroke()
  • background()

Using Parsons problems in class

  • Give each problem one correct order.
  • Use real code, and say what the finished program should do.
  • Repeat the concept across several similar problems.
  • Add distractor lines only for confident students.
